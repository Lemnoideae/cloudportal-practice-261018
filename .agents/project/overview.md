# 프로젝트 목적과 범위

## 목적

기존 Java 기반 프로젝트를 Kotlin으로 마이그레이션할 때 필요한 설계·구현 역량을 연습한다. Kotlin–Spring Boot로 사내 클라우드 인프라 자원 신청 및 승인 포털을 구현하며, Spring Security를 중심으로 업무 규칙과 보안 경계를 연결한다.

## 구현 범위

| 대상 | 핵심 기능 |
| --- | --- |
| 자원 신청서 | 인스턴스 타입, 사용 목적, 예상 비용을 포함한 신청·조회·수정·취소 |
| 승인/반려 히스토리 | 결정과 사유 기록, 처리 경과 조회 |
| 자원 스펙 카탈로그 | 신청 가능한 자원 스펙의 등록·조회·수정·삭제 정책 |

사용자 역할과 리소스 접근 규칙은 [인증과 인가](../security/authentication-authorization.md), 신청 생명주기는 [도메인과 상태 머신](../domain/resource-requests.md)을 기준으로 한다. 실제 클라우드 자원 프로비저닝은 별도 요청이 있을 때 범위를 정한다.

## 학습 우선순위

1. **인증과 인가의 분리**: 사용자를 식별하는 과정과 특정 자원에 대한 행위를 허용하는 판단을 각각 설명하고 검증할 수 있어야 한다.
2. **Kotlin–JPA 매핑**: Kotlin의 기본 불변성·final·nullable 타입이 JPA의 생성·프록시·변경 감지와 만나는 지점을 이해한다.
3. **Null Safety와 DTO 검증**: 컴파일 시점의 null 제약, JSON 바인딩, Bean Validation, 도메인 검증의 책임을 구분한다.
4. **상태 머신**: `enum class`와 `sealed class`를 함께 사용해 상태 표현과 허용된 전이를 명시하고, 불법 전이를 검증한다.

설계 선택은 이 학습 목표와 업무 규칙으로 설명한다. Java 문법을 기계적으로 치환하기보다 외부 계약을 유지하면서 Kotlin의 타입과 캡슐화를 활용한다.

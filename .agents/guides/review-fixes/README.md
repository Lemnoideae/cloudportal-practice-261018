# 리뷰 수정 가이드

2026-10-18 리뷰를 바탕으로, 현재 코드에서 무엇을 왜 바꾸는지 설명한다. 아래 코드는 **적용할 수정 예시**이며, 이 문서 작성으로 애플리케이션 소스가 수정되지는 않는다. 기존 파일의 메서드·필드 교체 예시에서는 package와 일부 import를 생략한다.

업무 정책의 원본은 [도메인](../../domain/resource-requests.md)과 [인증·인가](../../security/authentication-authorization.md) 문서다. 이 가이드는 해당 정책을 코드에 적용하는 방법을 다룬다.

## 적용 순서

| 순서 | 적용할 내용 | 완료 기준 |
| --- | --- | --- |
| 1 | [기동과 회원가입](01-startup-and-signup.md) | 컴파일 성공, 매핑 충돌 없이 기동, 일반 가입으로 관리자 권한 획득 불가 |
| 2 | [서비스 인가와 트랜잭션](02-authorization-and-transactions.md) | 컨트롤러 외 서비스 호출에서도 인가 적용, 신청 저장 성공 |
| 3 | [상태 전이와 동시성](03-state-and-concurrency.md) | 대기 상태에서만 처리, 경쟁하는 결정 중 하나만 커밋 |
| 4 | [후속 기능 구현](04-follow-up-features.md) | 비용·수정·이력·카탈로그를 정책과 함께 연결 |
| 5 | [검증 시나리오](05-verification.md) | 성공·거부·충돌을 HTTP 및 DB 결과로 확인 |

먼저 기존 enum 기반 동작을 복구하고, 그다음 sealed 상태 머신으로 옮긴다. 두 단계의 전이 검증을 최종 코드에 중복해서 남기지 않는다.

## 리뷰 항목과 적용 위치

| 리뷰 항목 | 적용 문서 |
| --- | --- |
| nullable User 저장으로 컴파일 실패, JWT 설정 문자열 오타 | 1 |
| 가입 요청의 역할을 그대로 저장하는 권한 상승 | 1 |
| 신청/취소의 POST 경로 충돌, 전체 조회 매핑 누락 | 1 |
| `requestSecurity` 빈 이름 불일치 | 2: 소유권 판단을 서비스로 옮겨 해당 참조 제거 |
| 생성 메서드의 읽기 전용 트랜잭션, 컨트롤러에만 있는 인가 | 2 |
| 취소 상태 조건 역전, 완료 신청 재승인, 동시 결정 덮어쓰기 | 3 |
| 비용·수정 API·결정 이력·카탈로그·sealed 모델 미구현 | 3, 4 |
| 권한 예외 타입 | 현재 소스는 Spring `AccessDeniedException` import가 추가됨. 5에서 응답 검증 |

## 수정 후 요청 흐름

```text
JWT 필터: 서명·유효기간 검증 → 인증된 principal
컨트롤러: JSON 바인딩·DTO 검증 → principal.id 전달
서비스 프록시: 역할·전달된 사용자 ID와 principal의 일치 확인
쓰기 트랜잭션: 신청 조회 → 소유권 확인 → 도메인 전이 → 이력 저장
커밋: 버전 충돌 검사 → 전체 반영 또는 전체 롤백
오류 처리: 인증 401 / 인가 403 / 입력 400 / 상태·동시성 충돌 409
```

서비스에 전달하는 사용자 ID는 요청 본문에서 받지 않는다. 서비스 인가는 다른 호출자가 임의의 사용자 ID를 전달하는 경우도 차단한다.
